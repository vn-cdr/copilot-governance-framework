## コマンド

- セットアップ：`[npm ci]`
- ビルド：`[npm run build]`
- テスト（全体）：`[npm test]`
- テスト（単体ファイル）：`[npm test -- path/to/file]`
- lint / 型チェック：`[npm run lint && npm run typecheck]`
- フォーマット：`[npm run format]`

## 作業の進め方

1. 変更前に関連コードと既存テストを読み、方針を短く説明してから着手する。
2. 大きな変更（複数モジュールにまたがる、設計変更を伴う）は、実装前に計画を提示して承認を得る。
3. 変更したら、テスト・lint・型チェックを実行し、すべて通ることを確認してから完了とする。
4. 完了報告には「変更内容」「実行した検証と結果」「未解決事項」を含める。

## テスト方針

- 機能追加・バグ修正には必ずテストを追加する。
- バグ修正では、まず再現するテストを書いて失敗を確認してから修正する。
- テストを通すためにテスト自体を弱める（アサーション削除、skip追加）ことは禁止。必要な場合は理由を説明して確認を取る。

## 禁止事項

- `main` / `[release/*]` ブランチへの直接push、および `git push --force`。
- 本番環境のリソース・データベースへの接続や変更。
- シークレット（APIキー、トークン、`.env`の中身）の出力・コミット。
- 依存パッケージの追加・メジャーバージョン更新を無断で行うこと（理由を説明して確認を取る）。
- [`infra/` で `terraform apply` を実行すること。planまでとする]

## 判断に迷ったとき

- 仕様が曖昧な場合は、推測で進めず質問する。
- 指示とこのファイルの内容が矛盾する場合は、作業を止めて確認する。
- 想定外のエラーが続く場合（目安：同じ問題で3回失敗）は、状況を報告して判断を仰ぐ。

## 長いタスクの進捗管理

- 複数セッションにまたがる作業では、`[PROGRESS.md]` に完了済み・作業中・次のステップを記録する。
- セッション開始時は、まず `[PROGRESS.md]` を読んで続きから再開する。
