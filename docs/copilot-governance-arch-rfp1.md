## 1. 前提

### 1.1 環境

| 項目 | 前提 |
|---|---|
| プラットフォーム | GitHub Enterprise Cloud（GHESは対象外） |
| 規模 | 約5,000ユーザー（全員がGHECライセンス保有と仮定）／約5,000リポジトリ |

### 1.2 GitHub Enterpriseプラン（Copilot access）の仕様（一次情報）

| 項目 | 内容 |
|---|---|
| シート料 | GHECライセンス保有者は**$0**。GHECライセンスがないユーザーは「Copilot Standalone」で月$10 |

### 2.2 GitHub Enterpriseプラン特有の課題

| # | 課題 | なぜ問題か | 本書での対応 |
|---|---|---|---|
| E1 | **含有クレジットがなく全量従量** | シート料という自然な上限がなく、**予算設定が唯一の歯止め**になる | §4.6で予算を多層化し、上限到達時の停止を必須化 |
| E2 | **シート割当が必要** | 「Enterpriseに含まれる＝全員が自動で使える」ではない。割当の設計が必要 | IdP同期のエンタープライズチームで割当（§4.1） |
| E3 | **Copilot Business／Enterpriseと混在不可** | 一部組織だけ従来プランを残すといった段階移行ができない | 移行はエンタープライズ単位で一括判断（§2.3 D1） |
| E4 | **アカウントチーム経由のみ** | セルフサービス契約では現時点で利用不可 | 契約形態の確認を最初のアクションにする |
| E5 | **Enterpriseエンドポイントへの切替** | プロキシ・FWが`*.business.githubcopilot.com`のみ許可の場合、利用が止まる | ネットワーク許可リストの更新を移行チェックリストに含める |
| E6 | **Copilot Enterprise相当の機能がすべて対象** | Business相当より利用面（クラウドエージェント、Spaces等）が広く、統制対象も増える | 既定で無効化し、段階的に開放（§3） |
| E7 | **ポリシーが及ぶのはエンタープライズ付与シートのみ** | 個人プランの利用者が社内リポジトリで機能を使う経路は、通常のポリシーでは止まらない | 「全リポジトリでブロック」系ポリシーとEMUで遮断（§4.4） |

### 2.3 未決事項（社内で決める必要があること）と推奨案

| # | 未決事項 | 選択肢 | 推奨案と理由 |
|---|---|---|---|
| D1 | Copilot accessへ移行するか | (a) 移行 (b) Copilot Business継続 (c) Copilot Enterprise継続 | **(a)を推奨（条件付き）**。§4.6の試算のとおり、同単価なら帳簿上は従来プラン以下のコストになる。条件は「予算を多層で設定できること」と「アカウントチーム経由で契約できること」 |
| D2 | 承認モデルの範囲 | 全モデル／ベンダー限定／個別承認 | **社内承認済みAIのベンダー（例：Anthropic・OpenAI）系に限定**し、新モデルは手動承認。Fusionもこの範囲内でのみ動作させる |
| D3 | BYOK（個人キー・ローカルモデル）を許可するか | 許可／禁止 | **禁止（ポリシーで無効化）**。承認外プロバイダへの経路になり、ローカルモデルは安全保護が異なる |
| D4 | エージェント機能の開放範囲 | 全面／段階／不可 | **段階開放**。IDEエージェントモード→CLI→クラウドエージェント（対象リポジトリ限定）の順 |
| D5 | MCPの扱い | 全面禁止／許可リスト／自由 | **許可リスト方式**（全面禁止はシャドー化を招く） |
| D6 | ローカルセッションのクラウド同期 | 無効／閲覧のみ／有効 | **初期は無効**。保持・閲覧範囲を法務が確認してから判断 |
| D7 | 予算の水準 | ユーザー単価・組織・全体 | パイロット実測の**中央値の2〜3倍をユーザー上限**とし、全体予算は月次見積り＋20%程度 |
| D8 | GHASの導入 | なし／Secret Protectionのみ／フル | 予算がつくなら**Secret Protectionを機密度の高いリポジトリから優先導入**。なしの場合は§4.8の代替策 |
| D9 | エンタープライズ予算の超過時の挙動 | 停止／継続 | **停止**。業務影響が許容できない組織だけコストセンター予算を厚くする |

### 2.4 GitHub・アカウントチームへの確認事項（不明点）

1. 当社の契約形態でCopilot accessが利用可能か。移行可能な最短の月初日はいつか。
2. 当社固有の価格（AIクレジット単価、割引）。本書は1クレジット＝$0.01と**推定**して試算している（Businessの$19に1,900クレジットが含まれることからの逆算）。
3. Copilotのプロンプト・応答・セッションの保持期間（surface別）。github.com上のチャット／エージェントセッションの最新の扱い。
4. Copilot access移行後も、既存のポリシー・予算・managed-settingsがそのまま引き継がれるか。
5. 個人プラン（Copilot Free／Pro）利用者が社内リポジトリでチャット等を使う経路を、EMU以外の方法で遮断できる範囲。
6. managed-settings.jsonの各キーが、現行のどのクライアント（VS Code、JetBrains、CLI、Copilot app、クラウドエージェント）で強制されるか。

## 3. 基本方針（§2への回答）

1. **既定は閉じ、承認したものだけ開ける**：新機能・新モデルは自動有効化させない。
2. **技術で強制できるものは強制する**：モデル、BYOK、MCP、エージェント権限、ネットワーク、ブランチ保護、予算は設定で担保する。
3. **ルールは短く、ユーザー責任の「標準」に絞る**：開発者が読む文書は3本に限定する（§5）。
4. **エージェントは別リスクとして段階開放**：補完・チャットとは効く統制が異なる。
5. **コストは予算で物理的に止める**：Copilot accessでは予算が唯一の上限になる。

## 4. 必要なGitHub設定

凡例：確度＝**一次**（GitHub公式で今回確認）／**引継**（v1調査時点の情報で今回は未再確認）。GHAS＝「不要」は追加ライセンス不要、「SP」はSecret Protection、「CS」はCode Securityが必要。

### 4.1 契約・ライセンス・ID

| 設定 | 推奨値 | 理由 | 確度 |
|---|---|---|---|
| 課金モデル | Copilot access（エンタープライズ単位で一括移行） | §2.3 D1 | 一次 |
| Copilotシート割当 | **IdP同期のエンタープライズチーム**単位で割当。フェーズごとにチームを拡大 | 自動付与されないため、申請レスで割当を管理できる方式にする | 一次 |

| SSO／SCIM | OIDC（Entra ID）＋条件付きアクセス | 退職者の即時無効化 | 引継 |
| IP許可リスト | 社内・VPNのみ | 端末外からのアクセス制限 | 引継 |
| ネットワーク許可リスト | `*.enterprise.githubcopilot.com`を追加 | Copilot accessはEnterpriseエンドポイントを使用 | 一次 |
| AIマネージャー用カスタムロール | AI Controlsの管理、監査ログ閲覧、Copilotメトリクス閲覧の権限 | Owner権限を増やさずに運用を委任 | 引継 |

| リポジトリ作成 | Privateのみ許可 | 引継 |
| 可視性の変更・削除・移管 | Enterprise Owner／Org Ownerのみ | 引継 |

### 4.3 AI Controls：モデル

| 設定 | 推奨値 | 理由 | 確度 |
|---|---|---|---|
| リリース済みモデルの既定での利用可否 | **無効（手動承認）** | 新モデルの自動開放を防ぐ | 引継 |
| 個別モデルポリシー | 承認ベンダー系のみ有効 | §2.3 D2 | 一次（ポリシーの存在） |
| Copilot Fusion | 有効化する場合は、**Fusion用の選択肢からも承認外モデルを除外**する（Fusionはモデルポリシーで有効なモデルのみ使用し、Fusion用だけ個別に無効化も可能） | 自動ルーティングでも承認範囲を超えないようにする | 一次 |
| Fusionのローカルモデル選択 | 使用しない（実験的機能、ローカルモデルは安全保護が異なる） | 品質・安全性が未評価 | 一次 |
| **BYOK（VS Code等の個人キー・ローカルモデル）** | **無効**（「Bring Your Own Language Model Key in VS Code」等のポリシー。**既定は有効**） | 承認外プロバイダへの経路になる | 一次 |
| Enterprise BYOK（カスタムモデル） | 無効（パブリックプレビュー） | 必要になった時点で個別評価 | 一次 |
| モデルポリシーのAPI管理 | Enterprise／チーム／組織レベルのモデルポリシーAPIでIaC化 | ドリフト防止 | 引継 |

### 4.4 AI Controls：機能・エージェント

| 設定 | 推奨値 | 理由 | 確度 |
|---|---|---|---|
| 新機能の既定ポリシー | **無効** | 新機能の自動有効化を防ぐ | 引継 |
| パブリックコードに一致する提案 | **ブロック** | ライセンス汚染の防止 | 引継 |
| Copilot CLI | フェーズ3まで無効。開放は希望チームのみ | シェル実行を伴う | 引継 |
| GitHub Copilot app | CLIと同時期まで無効（Business／Enterpriseユーザーが使うにはCLIポリシーの有効化が必要） | エージェントセッションを伴う | 一次（CLI依存）／引継 |
| Copilot in the cloud（クラウドエージェント） | フェーズ4まで無効 | 自律実行のため | 引継 |
| **Copilot cloud agentを全リポジトリでブロック** | フェーズ4まで**有効（ブロック）** | 個人プランや他エンタープライズからの利用も含めて遮断できる | 一次 |
| Copilot code review | フェーズ1から有効（予算設定後）。開放前は「全リポジトリでブロック」を使う | 人間レビューの補助 | 一次 |
| サードパーティエージェント／Agent apps | 無効 | 承認外AIの経路を閉じる | 引継 |
| **Store local sessions in the Cloud** | 初期は**無効**（ローカルのみ保存） | 同期データの保持・閲覧範囲が確認できるまで | 一次 |
| Copilot Memory、Spaces、Web検索、Connectors | 初期は無効、個別評価 | 情報の持続・外部送信を伴う | 引継 |
| プレビュー機能 | 無効（パイロット群のみ評価） | プレリリース条項 | 引継 |
| AI credits paid usage | **有効のまま**（Copilot accessでは必須） | 無効だとクレジット消費機能が使えない | 一次 |

### 4.5 managed-settings.json（`.github-private`リポジトリの`copilot/managed-settings.json`）

```json
{
  "permissions": {
    "disableBypassPermissionsMode": "disable",
    "deny": [
      "Read(./.env)",
      "Shell(git push --force *)",
      "Shell(rm -rf *)",
      "Shell(terraform destroy *)"
    ]
  },
  "allowedMcpServers": [
    { "serverUrl": "https://mcp.internal.example.co.jp/*" }
  ],
  "deniedMcpServers": [],
  "forceRemoteSettingsRefresh": true
}
```

- キー名・挙動はv1調査時点の情報（**引継**）。各キーがどのクライアントで強制されるかは、導入時に公式リファレンス「Enterprise managed settings」で確認すること（§2.4-6）。
- `allowedMcpServers`が未設定ならすべて許可、空配列ならすべてブロック。`deniedMcpServers`が常に優先（引継）。
- Fusionを既定モデルにする設定もmanaged-settingsで可能（一次）。

### 4.6 予算（Copilot accessでは最重要）

**試算（1クレジット＝$0.01と推定。§2.4-2で要確認）**

| 項目 | Copilot Business（5,000名） | Copilot access（5,000名・全員GHECライセンス保有） |
|---|---|---|
| シート料 | $95,000／月 | $0 |
| 含有クレジット | 950万（$95,000相当）をプール | なし |
| 利用額が月$60,000の場合 | $95,000（未使用枠は失効） | **$60,000** |
| 利用額が月$150,000の場合 | $95,000＋超過$55,000＝$150,000 | **$150,000** |
| 示唆 | 利用が少ないと割高 | 同単価なら常にBusiness以下。ただし**上限は予算だけ** |

**予算設定**

| 設定 | 推奨値 | 確度 |
|---|---|---|
| ユーザー単位の共通上限（Universal user-level budget） | パイロット実測の中央値の2〜3倍。到達時は課金機能が停止 | 引継 |
| コストセンター単位のユーザー上限 | 事業部ごとに設定 | 引継 |
| 個別ユーザー上限 | 例外時のみ、有効期限付き | 引継 |
| コストセンター／組織／エンタープライズ予算 | 設定し、**「上限到達時に利用を停止」を必ず有効化**（既定はオフ） | 引継 |
| 予算申請（Manage budget requests） | 例外申請の窓口として利用 | 一次（機能の存在） |
| アラート | 50%／75%／90%で通知 | 引継 |

> 予算が尽きても**ユーザーのアクセス自体は失われない**が、チャット・code review・Copilot in the cloud等は利用可能な予算を必要とする（二次情報。公式の挙動確認を推奨）。

### 4.7 組織：コンテンツ除外・クラウドエージェント

| 設定 | 推奨値 | 確度 |
|---|---|---|
| コンテンツ除外 | `**/.env*`、`**/secrets/**`、`**/*.pem`、`**/*.key`、顧客データのサンプル等 | 一次 |
| コンテンツ除外の位置付け | **IDE・CLI・Copilot app・クラウドのチャット／エージェントにも適用される**。ただし間接的なアクセスは検知できない場合があり、シンボリックリンクとリモートファイルシステムは対象外。**OS権限・アクセス制御の代替にはならない** | 一次 |
| 組織カスタム指示 | セキュアコーディング規約の要点、ハードコード禁止など | 引継 |
| クラウドエージェントのファイアウォール | 組織で有効を強制、リポジトリ側の独自ルールは不許可 | 引継 |
| クラウドエージェントのワークフロー実行 | 承認必須を維持 | 引継 |
| copilot環境のシークレット | 原則登録しない | 引継 |
| クラウドセッションの共有 | Actions上のセッションは**リポジトリ閲覧者に既定で共有される**ことを利用規程で周知。高機密リポジトリは対象外にする | 一次 |
| 対象リポジトリ | `copilot_agent_allowed=true`のリポジトリのみ | 引継 |
