## 第1章 前提とスコープ

### 1.1 環境

| 項目 | 前提 |
|---|---|
| プラットフォーム | GitHub Enterprise Cloud（GHESは対象外） |
| 規模 | **1,000ユーザー以上**（全員がGHECライセンス保有と仮定）、**1,000リポジトリ以上** |
| リポジトリ可視性 | 数名の管理者以外はprivateのみ |
| Copilotの提供方式 | **Copilot Enterprise相当**：GitHub Enterpriseプランに含まれる「Copilot access」を第一候補、Copilot Enterpriseを代替とする |
| GHAS | 追加費用のため未導入の可能性あり。「あり／なし」を併記 |
| 承認済み生成AI | 限定的（例：Claude・ChatGPTのみ）。Copilot内のモデルも同じ範囲に合わせる想定 |
| 運用方針 | 申請・例外処理を最小化し、ユーザー責任の「標準」を中心にする |

### 1.2 スコープ外

- **Copilot Business**（同一エンタープライズ内でCopilot accessと混在できないため、比較・設定の対象外とする）
- GHES
- 個人プラン（Copilot Free／Pro／Pro+／Max）の業務利用。禁止の対象としてのみ扱う
- 一般的なソフトウェアサプライチェーン対策と、ランナーのEgress制御（→1.4）

### 1.3 提供方式の比較（Copilot Enterprise相当の2方式）

| 項目 | Copilot access（GitHub Enterpriseプラン同梱） | Copilot Enterprise |
|---|---|---|
| シート料 | GHECライセンス保有者は**$0**（非保有者はCopilot Standaloneで月$10） | 月$39／ユーザー |
| 含有AIクレジット | **なし**（初回利用から従量） | 3,900／ユーザー／月（エンタープライズ内でプール） |
| 機能・モデル | Copilot Enterpriseと同等 | ― |
| シート割当 | 必要（自動では付与されない） | 必要 |
| 契約経路 | 2026-10-28時点ではGitHub／Microsoftのアカウントチーム経由のみ。セルフサービスは段階的に開放予定 | 通常購入 |
| 移行 | 任意。月初1日付で発効 | ― |

確度：公式

**試算（1クレジット＝$0.01と推定。Copilot Enterpriseの$39に3,900クレジットが含まれることからの逆算で、当社の契約単価は要確認）**

1,000名、全員GHECライセンス保有の場合。

| 月間の利用額 | Copilot Enterprise | Copilot access |
|---|---|---|
| $20,000 | $39,000（未使用枠は失効） | **$20,000** |
| $39,000 | $39,000 | $39,000 |
| $60,000 | $39,000＋超過$21,000＝$60,000 | $60,000 |

示唆：単価が同じなら、Copilot accessは常にCopilot Enterprise以下のコストになる。ただし**シート料という上限がなく、予算設定が唯一の歯止め**になる（→4.6）。

### 1.4 前提とする既存の取り組み（本書の対象外）

AIの有無にかかわらず必要な対策は、別途検討する次の取り組みで定義・実装する。本書はこれらが整備されていることを前提とし、内容は記載しない。

| 取り組み | 主な範囲 |
|---|---|
| **DevSecOpsフレームワーク** | Actionsの許可リスト・SHAピン留め、GITHUB_TOKENの権限、OIDC、Dependabot、SBOM、Artifact attestations、CIでの依存関係・シークレット・SAST検査 |
| **ランナーのEgress制御** | 自社ランナー（セルフホスト／ラージランナー）からの外部通信の制限 |

**本書との分担**：判断基準は「AIが新たに持ち込む、またはAIによって大きくなるリスクかどうか」。該当するものは本書、該当しないものは上記の取り組みで扱う。

| 項目 | 本書（AIガバナンス） | DevSecOpsフレームワーク／ランナーのEgress制御 |
|---|---|---|
| モデル、MCP・プラグインの入手元 | 決定・設定（→4.3、4.5） | ― |
| AIが提案する依存パッケージ | レビュー基準として実在確認を定める（→第5章③） | CIでの検査 |
| 指示ファイル（AGENTS.md等）の保護 | CODEOWNERSの対象に指定（→4.2） | フレームワークのリポジトリ構成に組み込み |
| クラウドエージェントの外部通信 | 要件を定める（→4.7） | 自社ランナーで動かす場合はEgress制御で実装 |
| エージェントが変更したワークフローの実行 | 人の承認を必須とする（→4.7） | ― |
| Actionsの許可リスト、SHAピン留め、Dependabot、SBOMなど | 対象外 | 定義・実装 |

### 2.3 GitHub Enterpriseプラン特有の課題

| # | 課題 | 問題になる理由 | 対応（参照先） |
|---|---|---|---|
| E1 | 含有クレジットがなく全量従量 | シート料という上限がなく、予算設定が唯一の歯止めになる | 予算を多層化し、上限到達時の停止を必須にする（→4.6） |
| E2 | シート割当が必要 | 「Enterpriseに含まれる＝全員が自動で使える」ではない | IdP同期のエンタープライズチームで割当。GitHub AppによるAPI自動化（→4.1） |
| E3 | 他のCopilotプランと混在不可 | 組織単位の段階移行ができない | 移行はエンタープライズ単位で一括判断（→2.4 D1） |
| E4 | アカウントチーム経由のみ | セルフサービス契約では現時点で利用不可 | 契約形態の確認を最初のアクションにする（→第8章） |
| E5 | 接続先がEnterpriseエンドポイントに切り替わる | FWが`*.business.githubcopilot.com`のみ許可だと利用が止まる | 許可リストに`*.enterprise.githubcopilot.com`を追加（→4.1） |
| E6 | Copilot Enterprise相当の全機能が対象 | 統制対象の機能が多い | 既定で無効にし、段階的に開放（→3.3、4.4） |
| E7 | 通常のポリシーが及ぶのは自社付与のシートのみ | 個人プラン利用者や、別アカウントでリポジトリを扱う経路が残る | 全リポジトリでブロックするポリシー、EMU、利用規程（→4.4、第5章①） |

### 2.4 未決事項（社内で決める必要があること）と推奨案

| # | 未決事項 | 推奨案と理由 |
|---|---|---|
| D1 | Copilot accessとCopilot Enterpriseのどちらにするか | **Copilot accessを推奨（条件付き）**。単価が同じなら常に同等以下のコスト（→1.3）。条件は、予算を多層で設定できることと、アカウントチーム経由で契約できること |
| D2 | 承認モデルの範囲 | 社内承認済みAIのベンダー系に限定。新モデルと代替モデルは手動承認。Fusionもこの範囲に限定 |
| D3 | データ保持が必要なモデル（例：Claude Fable 5.2）を許可するか | 法務がデータ保持条件を確認するまで**無効のまま**（既定オフを維持） |
| D4 | BYOK（個人キー・ローカルモデル）を許可するか | **禁止**。承認外プロバイダへの経路になり、ローカルモデルは安全保護が異なる |
| D5 | エージェント機能の開放範囲 | 段階開放。IDEエージェントモード→CLI／Copilot app→クラウドエージェント（対象リポジトリ限定） |
| D6 | MCP・スキル・カスタムエージェントの配布方法 | **プラグイン経由に限定**（strictPluginOnlyCustomization）し、社内マーケットプレイスで配布 |
| D7 | ローカルセッションのクラウド同期 | 初期は無効。保持・閲覧範囲を法務が確認してから判断 |
| D8 | 予算の水準 | パイロット実測の中央値の2〜3倍をユーザー上限にする。全体予算は月次見積り＋20%程度 |
| D9 | GHASの導入 | 予算がつくなら、機密度の高いリポジトリからSecret Protectionを優先導入。導入しない場合は4.8の代替策 |

### 2.5 GitHub・アカウントチームへの確認事項

1. 当社の契約でCopilot accessを利用できるか。移行可能な最短の月初日。
2. 当社のAIクレジット単価と割引条件。
3. surfaceごとのプロンプト・応答・セッションの保持期間。データ保持が必要なモデルの具体的な条件。
4. 移行後も既存のポリシー・予算・managed-settingsが引き継がれるか。
5. 個人プラン利用者と、Copilot appの「ライセンスとリポジトリで別アカウント」機能を、EMU以外の方法で統制できる範囲。
6. managed-settingsの各キーが、どのクライアント（VS Code、JetBrains、CLI、Copilot app、クラウドエージェント）で強制されるか。

## 第3章 基本方針と段階導入

### 3.1 基本方針

1. **既定は閉じ、承認したものだけ開ける**：新機能・新モデル・代替モデルを自動で有効化させない。
2. **技術で強制できるものは強制する**：モデル、BYOK、カスタマイズの配布元、エージェント権限、ネットワーク、ブランチ保護、予算は設定で担保する。
3. **ルールは短く、ユーザー責任の「標準」に絞る**：開発者が読む文書は3本に限定する（→第5章）。
4. **エージェントは別リスクとして段階開放する**。
5. **コストは予算で物理的に止める**。

### 3.2 体制（RACIの要点）

| 活動 | 説明責任 | 実行 |
|---|---|---|
| ポリシー策定・モデル／機能の承認 | AIガバナンス委員会（議長：CISO） | AIマネージャー |
| AI Controls・managed-settings・予算の設定 | AIマネージャー | AIマネージャー |
| ルールセット・ブランチ保護 | Enterprise Owner | Org Owner、リポジトリ管理者 |
| MCP・プラグインの審査 | セキュリティ | AIマネージャー |
| AI生成コードのレビュー | リポジトリ管理者 | 開発者 |
| インシデント対応 | セキュリティ | AIマネージャー |

AIマネージャーには、Enterprise Ownerの代わりに、AI Controlsの管理・監査ログ閲覧・メトリクス閲覧の権限を持つカスタムロールを付与する（前版）。

### 3.3 段階導入（規模に応じて比率で設定）

| フェーズ | 期間目安 | 対象 | 開放する機能 | 次へ進む条件 |
|---|---|---|---|---|
| 0 基盤 | 1〜2か月 | 管理者 | 契約、ネットワーク、EMU／IdP、AI Controlsの既定値、予算、監査ログ、ルールセット、managed-settings | 第4章のチェックリストを完了 |
| 1 パイロット | 2〜3か月 | 全体の**5〜10%**（複数部門、若手とベテランを混在） | IDE補完、IDEチャット、github.comチャット、code review | 品質指標の悪化なし、コスト実測値の取得 |
| 2 拡大 | 2〜4か月 | 全体の**30〜50%** | ＋IDEエージェントモード（bypass禁止、ローカルサンドボックス有効） | 教育修了率95%以上、予算内 |
| 3 全社 | 以降 | 全員 | ＋承認済みプラグイン（MCP含む）、CLI／Copilot app（希望チーム） | 四半期レビューで承認 |
| 4 エージェント拡張 | 個別 | 選定チーム | クラウドエージェント（対象リポジトリ限定）、自動化 | 個別のリスク評価で承認 |

## 第4章 必要なGitHub設定

凡例：「GHAS」欄の「不要」は追加ライセンス不要、「SP」はSecret Protection、「CS」はCode Securityが必要という意味です。

### 4.1 契約・ライセンス・ID

| 設定 | 推奨値 | 理由 | 確度 |
|---|---|---|---|
| 課金モデル | Copilot access（エンタープライズ単位で一括移行） | 2.4 D1 | 公式 |
| Copilotシート割当 | IdP同期のエンタープライズチーム単位。フェーズごとにチームを拡大 | 自動付与されないため、申請なしで管理できる方式にする | 公式 |

### 4.5 managed-settings（`.github-private`リポジトリの`copilot/managed-settings.json`）

```json
{
  "permissions": {
    "disableBypassPermissionsMode": "disable",
    "deny": [
      "Read(./.env)",
      "Shell(git push --force *)",
      "Shell(rm -rf *)",
      "Shell(terraform destroy *)"
    ]
  },
  "strictPluginOnlyCustomization": ["mcpServers", "extensions", "hooks"],
  "allowedMcpServers": [
    { "serverUrl": "https://mcp.internal.example.co.jp/*" }
  ],
  "deniedMcpServers": [],
  "forceRemoteSettingsRefresh": true
}
```

| 項目 | 内容 | 確度 |
|---|---|---|
| strictPluginOnlyCustomization | スキル、カスタムエージェント、フック、MCPサーバー、拡張機能の5分類から選んで、ユーザー・プロジェクト単位の独自設定を遮断し、プラグインまたはmanaged settings由来のみ許可する。**エンタープライズ管理のプラグインのみという意味ではなく、マーケットプレイスの許可リストでもない**ため、マーケットプレイス制限と組み合わせる | 公式（11/16） |
| 値の書式 | 上記JSONの配列表記は例示。正式なキー値・書式は公式リファレンスで確認すること | ― |
| チーム単位のカスタマイズ | チームメンテナーがチームのマーケットプレイスからプラグインを選ぶと、メンバーに既定で有効になる。エンタープライズ／組織の制御は上書きされない。**チームメンテナーへの教育と、マーケットプレイス制限の併用が必要** | 二次（11/18） |
| ローカルサンドボックス | エージェントのファイル・ネットワーク・資格情報へのアクセスを制限する。CLI、Copilot app、VS Code（Agent Host）でGA、追加費用なし。フェーズ2以降は**有効化を標準**にする | 公式（10/09） |
| その他のキー（permissions、allowedMcpServers等） | `allowedMcpServers`が未設定なら全許可、空配列なら全ブロック、`deniedMcpServers`が常に優先 | 前版 |
